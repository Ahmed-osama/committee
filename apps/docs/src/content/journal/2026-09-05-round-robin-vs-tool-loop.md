---
title: "Why round-robin beats a single agent's tool loop"
date: 2026-09-05
tags: ['ai', 'architecture']
entryId: '2026-09-05-round-robin-vs-tool-loop'
---

<p>The committee's <code>runPlanningSession</code> deliberately isn't one LLM in a
      tool-calling loop deciding when to keep going — it's a plain <code>for</code> loop
      that hands the <em>full transcript</em> to a different agent (with a different
      system prompt, sometimes a different model) each turn. Watching the real-estate-app
      planning session run, this showed its value directly: the Architect proposed full
      user accounts, and it was a genuinely different agent — the Skeptic — that killed it
      ("forcing signup before any listing exists creates unnecessary friction"), then a
      third agent (Devil's Advocate) pushed a wild alternative (blockchain-backed listings)
      that got explicitly rejected rather than silently absorbed into scope.</p>
      <p>A single agent looping on its own tool calls tends to talk itself into agreement —
      each step is generated by the same weights with the same priors, so it rarely
      surfaces a genuinely different angle on its own. Rotating <em>which model</em> speaks
      each turn (see <code>rotateProviderOrder</code> in <code>provider-router.ts</code>)
      compounds this: different providers actually disagree sometimes, which is the whole
      point of a "skeptic" role having teeth instead of being decorative.</p>
